## 三、建仓流程

### 3.1 完整流程

```
开发者提交 Issue（选择"新建仓库申请"模板）
    │  填写 11 个字段：类型、名称、描述、可见性、许可证、Topics、人员、理由
    │
    ▼
表单校验（repo-request-validation.yml）
    │  repo_request_validator.py 校验：
    │  ├── 仓库名称格式（小写字母+数字+连字符，≤100字符，无连续连字符）
    │  ├── 仓库类型合法（9 种）
    │  ├── Topics ≥ 3 个，且每个 topic 匹配 [a-z0-9][a-z0-9.-]*
    │  └── Owner ≥1 人、Maintainer ≥1 人
    │
    ├── 不合规 → 评论列出具体错误 + 不进入审批（无 status/pending）
    │           用户编辑修正 → 重新校验
    │
    └── 合规 → 打 status/pending 标签 + 评论"等待审批" + 飞书通知管理员
            │
            ▼
        管理员审核（approve-repo.yml / reject-repo.yml）
            ├── 通过 → 运行 approve-repo.yml → 打 status/approved 标签
            │           ↓
            │      repo-creator.yml workflow 触发（on: labeled, status/approved）
            │           ↓
            │      建仓机器人执行（repo_creator.py）:
            │
            │      ├── 1. 解析表单 → 提取 11 个字段
            │      ├── 2. 校验（脚本内二次校验）
            │      │   ├── 仓库名称格式
            │      │   ├── Topics ≥ 3（非法 topic 静默丢弃）
            │      │   └── 无同名仓库
            │      ├── 3. 创建仓库（BOT_TOKEN，repo scope PAT）
            │      │   ├── 设置描述、可见性（public/private）
            │      │   ├── auto_init=True
            │      │   ├── Issues 开启、Projects 关闭、Wiki 关闭
            │      │   ├── Squash merge 开启、Merge/Rebase commit 关闭
            │      ├── 4. 初始化文件（按类型分级，详见 §3.3 矩阵）
            │      ├── 5. 设置 Topics 标签
            │      ├── 6. 开启安全告警 + 自动修复（Dependabot alerts/fixes）
            │      ├── 7. 分配角色权限
            │      │   ├── Owner → admin
            │      │   ├── Maintainer → maintain（不与 Owner 重复）
            │      │   └── Writer → push（不与 Owner/Maintainer 重复）
            │      ├── 8. GitCode 同步建仓（api.gitcode.com/api/v5）
            │      ├── 9. 飞书通知（交互式卡片：仓库信息 + GitHub/GitCode 链接）
            │      └── 10. 关闭 Issue（评论报告 + status/completed + close）
            │
            └── 拒绝 → 运行 reject-repo.yml → 评论说明原因 + 打 status/declined 标签
                        ↓
                    手动关闭 Issue
```

### 3.2 建仓表单字段

| # | 字段 | 类型 | 必填 | 说明 |
|---|------|------|:--:|------|
| 1 | 仓库类型 | dropdown (9选1) | ✅ | SDK / Terraform / Action / 框架集成 / Exporter / IoT / 示例 / 文档 / 内部 |
| 2 | 仓库名称 | input | ✅ | 正则：`[a-z0-9]([a-z0-9-]*[a-z0-9])?`，≤100字符，无连续连字符 |
| 3 | 仓库描述 | textarea | ✅ | 用于 GitHub Description |
| 4 | 可见性 | dropdown | ✅ | public / private |
| 5 | 开源许可证 | dropdown | ✅ | Apache-2.0(推荐) / MIT / BSD-3-Clause（注：仅产品项目使用用户选择，其余强制Apache-2.0） |
| 6 | Topics 标签（至少 3 个） | textarea | ✅ | ≥3 个，逗号/换行分隔；每个 topic 须匹配 `[a-z0-9][a-z0-9.-]*` |
| 7 | Owner（管理员，≥1 人） | textarea | ✅ | GitHub 用户名，逗号分隔 |
| 8 | Maintainer（维护者，≥1 人） | textarea | ✅ | GitHub 用户名，逗号分隔 |
| 9 | Writer（写入者） | textarea | | 可选 |
| 10 | 申请理由 | textarea | ✅ | 背景、解决的问题、目标用户 |
| 11 | 确认清单 | checkboxes | ✅ | 5 项确认：命名/重名/成员/治理规范 |

| 项目类型 | 许可证来源 | 说明 |
|----------|-----------|------|
| 产品项目（SDK/Action/Provider/框架/Exporter/IoT） | 用户选择 | Apache-2.0 / MIT / BSD-3-Clause |
| 示例教程（Lab/Sample） | 强制 Apache-2.0 | 忽略用户选择 |
| 文档数据（Docs/Dataset） | 强制 Apache-2.0 | 忽略用户选择 |

## 四、审批流程

```
Issue 创建
    ↓
表单校验（repo-request-validation.yml）
    ├── 合规 → 打 status/pending → 等待审批
    └── 不合规 → 评论列出错误 → 用户编辑修正 → 重新校验
    ↓
管理员审核（workflow_dispatch）
    ├── 通过 → 运行 Approve Repo Request workflow
    │           ↓
    │      打 status/approved 标签
    │           ↓
    │      repo-creator.yml 触发（on: labeled, label=status/approved）
    │           ↓
    │      checkout → 运行 scripts/repo_creator.py
    │           ↓
    │      自动创建 + 初始化 + 安全告警 + GitCode 同步 + 飞书通知 + 关闭 Issue
    │
    └── 拒绝 → 运行 Reject Repo Request workflow
                ↓
            评论说明原因 + 打 status/declined 标签
                ↓
            手动关闭 Issue
```

## 五、GitCode 同步建仓

- 使用 GitCode v5 API（`https://api.gitcode.com/api/v5`）
- 建仓时同步在 GitCode 创建同名仓库：`POST /orgs/hd-vector/repos`
- 新仓库注入 `sync-to-gitcode.yml` workflow（`oauth2:token` 认证）
- 后续 push 自动同步到 GitCode

## 六、Secrets 配置

| Secret | 仓库 | 说明 |
|--------|------|------|
| `BOT_TOKEN` | repository-requests | 有 repo scope 的 PAT，用于创建组织仓库 + 审批/拒绝打标签 |
| `GITHUB_TOKEN` | repository-requests | workflow 自动注入，用于 Issue 评论和标签操作 |
| `GITCODE_TOKEN` | repository-requests / org | GitCode API 认证（org 级 all 可见） |
| `GITCODE_USERNAME` | repository-requests / org | GitCode 用户名 |
| `FEISHU_APP_ID` | repository-requests | 飞书应用 ID |
| `FEISHU_APP_SECRET` | repository-requests | 飞书应用密钥 |
| `FEISHU_ADMIN_OPEN_ID` | repository-requests | 飞书通知接收人 open_id |

## 七、管理员操作速查

```powershell
# 查看待审批建仓申请（status/pending）
gh issue list -R huaweicloud-mate/repository-requests -l "status/pending"

# 审批建仓（通过）
gh workflow run "Approve Repo Request" -R huaweicloud-mate/repository-requests \
  -f issue_number=<编号>

# 拒绝建仓
gh workflow run "Reject Repo Request" -R huaweicloud-mate/repository-requests \
  -f issue_number=<编号> -f reason="拒绝原因"
```

## 八、标签体系

| 标签 | 用途 |
|------|------|
| `status/pending` | 已通过校验，等待审批 |
| `status/approved` | 已批准，触发建仓 |
| `status/declined` | 已拒绝 |
| `status/completed` | 建仓完成 |
| `request/create-repo` | 旧架构标签（已不再使用，仅兼容遗留 Issue） |
