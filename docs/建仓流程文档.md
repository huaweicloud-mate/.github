## 三、建仓流程

### 3.1 完整流程

```
开发者提交 Issue（选择"新建仓库申请"模板）
    │  填写 11 个字段：类型、名称、描述、可见性、许可证、Topics、人员、理由
    │
    ▼
自动打标签: status/pending + request/create-repo
    │  注：此步骤由 repo-creator.yml workflow 层实现，非脚本逻辑
    │
    ▼
管理员审核
    │  打 status/approved 标签 → 触发 repo-creator.yml → 调用 repo_creator.py
    │
    ▼
建仓机器人执行:
    │
    ├── 1. 解析表单 → 提取 11 个字段
    │
    ├── 2. 校验
    │   ├── 仓库名称格式（小写字母+数字+连字符，不以连字符开头/结尾，无连续连字符，≤100字符）
    │   ├── 无同名仓库
    │   ├── Topics ≥ 3 个，且每个 topic 须匹配 [a-z0-9][a-z0-9.-]*（非法字符自动丢弃）
    │   └── 非法 topic 静默丢弃，只保留合法项
    │
    ├── 3. 创建仓库（BOT_TOKEN，repo scope PAT）
    │   ├── 设置描述、可见性（public/private）
    │   ├── auto_init=True（GitHub 自动创建初始 commit）
    │   ├── Issues 开启、Projects 关闭、Wiki 关闭
    │   ├── Squash merge 开启（allow_squash_merge=True）
    │   ├── Merge commit 关闭（allow_merge_commit=False）
    │   └── Rebase merge 关闭（allow_rebase_merge=False）
    │
    ├── 4. 初始化文件（按类型分级，详见 §3.3 矩阵）
    │   ├── 产品项目 (SDK/Action/Provider/框架/Exporter/IoT)
    │   │   └── 14 项：LICENSE(按用户选择) + README(9套模板之一)
    │   │       + CONTRIBUTING + SECURITY + CoC
    │   │       + Issue模板×3(bug/feature/config) + PR模板
    │   │       + Dependabot(按生态匹配) + Triage workflow
    │   │       + GitCode sync workflow + 14标签 + 安全告警+自动修复
    │   │
    │   ├── 示例教程 (Lab/Sample)
    │   │   └── 7 项：LICENSE(强制Apache-2.0) + README + CONTRIBUTING
    │   │       + Issue模板×3 + PR模板 + 8标签 + 安全告警+自动修复
    │   │
    │   ├── 文档数据 (Docs/Dataset)
    │   │   └── 3 项：LICENSE(强制Apache-2.0) + README + 安全告警
    │   │
    │   └── 内部配置 (Workflow/Scripts)
    │       └── 2 项：LICENSE(强制Apache-2.0) + README
    │
    ├── 5. 设置 Topics 标签（经过正则校验后的合法 topic 列表）
    │
    ├── 6. 分配角色权限
    │   ├── Owner → admin
    │   ├── Maintainer → maintain（不与 Owner 重复）
    │   └── Writer → push（不与 Owner/Maintainer 重复）
    │
    ├── 7. 飞书通知（可选，需配置 FEISHU_APP_ID/APP_SECRET/ADMIN_OPEN_ID secrets）
    │   └── 交互式卡片：仓库信息 + 查看仓库/治理规范按钮
    │
    └── 8. 关闭 Issue
        └── 评论输出完整创建报告 + 打标签 status/completed + 自动 close
```

### 3.2 建仓表单字段

| # | 字段 | 类型 | 必填 | 说明 |
|---|------|------|:--:|------|
| 1 | 仓库类型 | dropdown (9选1) | ✅ | SDK / Terraform / Action / 框架集成 / Exporter / IoT / 示例 / 文档 / 内部 |
| 2 | 仓库名称 | input | ✅ | 正则：`[a-z0-9]([a-z0-9-]*[a-z0-9])?`，≤100字符，无连续连字符 |
| 3 | 仓库描述 | textarea | ✅ | 用于 GitHub Description |
| 4 | 可见性 | dropdown | ✅ | public / private |
| 5 | 开源许可证 | dropdown | ✅ | Apache-2.0(推荐) / MIT / BSD-3-Clause（注：仅产品项目使用用户选择，其余强制Apache-2.0） |
| 6 | Topics 标签（至少 3 个） | textarea | ✅ | ≥3 个，逗号/换行分隔；每个 topic 须匹配 `[a-z0-9][a-z0-9.-]*` |
| 7 | Owner（管理员，≥1 人） | textarea | ✅ | GitHub 用户名，逗号分隔 |
| 8 | Maintainer（维护者，≥1 人） | textarea | ✅ | GitHub 用户名，逗号分隔 |
| 9 | Writer（写入者） | textarea | | 可选 |
| 10 | 申请理由 | textarea | ✅ | 背景、解决的问题、目标用户 |
| 11 | 确认清单 | checkboxes | ✅ | 5 项确认：命名/重名/成员/治理规范 |

| 项目类型 | 许可证来源 | 说明 |
|----------|-----------|------|

## 四、审批流程

```
Issue 创建
    ↓
自动标签: status/pending + request/create-repo
    │  注：此步骤由 repo-creator.yml workflow 的 on.issues.labeled 事件触发
    │      脚本 repo_creator.py 仅检查 status/approved 是否存在，不负责初始打标
    ↓
管理员审核
    ├── 通过 → 打 status/approved 标签
    │           ↓
    │      repo-creator.yml workflow 触发
    │           ↓
    │      checkout → 运行 scripts/repo_creator.py
    │           ↓
    │      自动创建 + 初始化 + 关闭 Issue
    │
    └── 拒绝 → 评论说明原因 + 打 status/declined 标签
                ↓
            手动关闭 Issue
```

## 六、Secrets 配置

| Secret | 仓库 | 说明 |
|--------|------|------|
| `BOT_TOKEN` | repository-requests | 有 repo scope 的 PAT，用于创建组织仓库 |

| `FEISHU_APP_ID` | repository-requests | 飞书应用 ID（可选，缺则跳过通知） |
| `FEISHU_APP_SECRET` | repository-requests | 飞书应用密钥（可选） |
| `FEISHU_ADMIN_OPEN_ID` | repository-requests | 飞书通知接收人 open_id（可选） |

## 七、部署步骤

```
Step 1: 创建 huaweicloud/.github 仓库（14个文件）
        gh repo create huaweicloud/.github --public
        → 推送组织模板文件 + stale_manager.py

Step 2: 创建 huaweicloud/repository-requests 仓库（5个文件）
        gh repo create huaweicloud/repository-requests --public
        → 推送建仓机器人（含 repo_creator.py）

Step 3: 配置 Secrets
        gh secret set BOT_TOKEN --repo huaweicloud/repository-requests
        (可选) gh secret set FEISHU_APP_ID/APP_SECRET/ADMIN_OPEN_ID

Step 4: 测试
        提交测试建仓 Issue → 管理员 approve → 验证创建结果

Step 5: 存量仓库整改（按月计划 W1-W4 执行）
```
